## 2. Problem we solve

Villa ops often live in WhatsApp / group chat chaos:

- Job sent, unclear who accepted it  
- Wrong villa, address buried in the thread  
- Work done with no durable record of who or how much  
- Receipts as photos until month-end  
- Owner asks “is Coral done?” after the guest already checked in  
- Knowledge walks out when someone leaves  

**Pulse Flow picks up where chat fails:** confirmed jobs, costs on a property, history that stays with the company.

### Before → After (story to tell)

**Before:** group chat (owner asks, manager ping-pongs, cleaner confused, vendor says done in cash, owner still unsure).  

**After (in the app):** job activity trail, for example:

1. Job created (owner/manager)  
2. Accepted (staff / vendor · Read & agreed)  
3. On site  
4. Completed  
5. Receipt attached (e.g. 800 THB pending approval)  

Owner sees **Done** without chasing the chat.

## 3. What the product does

| Area | Promise |
| --- | --- |
| **Properties** | One list for owner, assigned manager, and person on site: status, map, stay dates, photo |
| **Jobs & vendors** | Assign work; staff can accept in-app; confirmed status |
| **Tasks** | Day-to-day work items (including urgent) tied to properties and people |
| **Money / bills** | Maintenance spend by property; receipts; approve when paid; exportable |
| **Guests** | House rules, deposit with deductions, date requests without using the owner’s personal number |
| **Languages** | Write once; each person reads jobs/chat in their profile language (e.g. English → Thai → Hebrew) |
| **Roles = screens** | Owner, manager, field staff, guest each get their own surface (no manual permission maze) |
| **Connect your agent** | In-app agent chat and/or external agent via connection key (MCP). Owners/managers only. Never hands over the database key. Part of **Pro** after trial |

**Platform today:** web app (mobile browser). Works like an app on the phone; no App Store required for staff.  
**App Store / Play:** planned later; timing depends on budget. Do **not** promise a store date.

## 4. Audience

### Primary (decide / pay)
- **Property owners** — often Israeli or foreign owners of villas, remote; want control, money trail, confirmed staff work  
- **Local operators / villa managers** — run the day; feel chat failure first  

### Secondary (use daily, free seats)
- **Field staff** — cleaners, maintenance, vendors: confirm jobs, send receipts  
- **Guests** — invited stay guests: rules, deposit, rebook requests  

### Beachhead
- **Koh Phangan / Thailand** first; hand onboarding  
- Prefer small–mid operators (roughly 1–15+ properties) who already feel WhatsApp pain  

### Owner motives (use in copy)
1. Remote control — see the day without calling the manager  
2. Money trail — every baht/shekel tied to a property  
3. Staff reliability — job accepted, not “maybe in WhatsApp”  
4. Language — write once, team reads in their language  
5. Serious product — looks like a tool you’d pay for, not a toy

## 12. Connect your agent (product, not this marketing bot)

Owners/managers can:

- Chat with an agent inside Pulse, or  
- Create a connection key in Settings → Connect your agent and paste into an MCP client (e.g. Cursor)  

Tools include (examples): `pulse_whoami`, `pulse_list_team`, `pulse_list_villas`, `pulse_list_tasks`, `pulse_create_task`, `pulse_update_task_status`, `pulse_list_jobs`, `pulse_create_job`, `pulse_list_bills`.  

Scoped to the company workspace; disconnect anytime. Staff and guests do not get this.
